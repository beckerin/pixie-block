Transações

Payments com line items; impostos resolvidos pelos tax_codes definidos em config/taxes.json.

POST /v1/transactions

Body

{
  "payer": "merchant_001",
  "payee": "person_001",
  "items": [
    {
      "description": "Serviço",
      "amount": 100000,
      "tax_codes": ["IBS", "CBS"],
      "discounts": []
    }
  ]
}
CampoDescrição
payer / payeeIDs de contas existentes
items[].amountCentavos (inteiro)
items[].tax_codesCódigos presentes em taxes.json (rate_bps + tax_account)
items[].discountsOpcional; valor absoluto para conta fiscal
Não envie tax_splits no body: o nó aplica as taxas a partir do genesis/taxes. Payee person não pode ter tax_codes nos items.

Assinatura

O nó assina a TX com a chave privada do payer no keystore local. Se o payer não estiver no keystore deste nó → erro.

Admissão

  1. Validação de contas, impostos e saldo (com reserva no mempool).
  2. 201 com a TX assinada.
  3. Gossip P2P; inclusão no próximo bloco do produtor.

Consulta

GET /v1/transactions/{id}

Busca no chain ou mempool. Com viewer (pkey), payload completo se for parte ou audit; caso contrário, visão pública redigida.

Blocos

GET /v1/blocks/latest
GET /v1/blocks/previous
GET /v1/blocks/{height}

Também sujeitos à redação por viewer. Ver Privacidade.

Exemplo com impostos (genesis demo)

Em config/taxes.json: IBS 17% → federal_treasury, CBS 11% → sao_paulo_treasury (rate_bps).

curl -s -X POST http://localhost/v1/transactions \
  -H 'Content-Type: application/json' \
  -d '{
    "payer": "merchant_001",
    "payee": "merchant_002",
    "items": [
      {
        "description": "NF",
        "amount": 100000,
        "tax_codes": ["IBS", "CBS"]
      }
    ]
  }' | jq .
