Privacidade

Leituras da API e do SSE usam um viewer derivado da chave privada. Não há middleware de login global.

Como identificar o viewer

  • Header X-Private-Key: <base64>, ou
  • Query ?pkey=<base64> (necessário para EventSource / SSE, que não envia headers customizados)

+ na chave pode virar espaço na URL; o servidor normaliza espaços de volta para +.

Níveis

ViewerComoO que vê
Anônimo Sem pkey / inválida Blocos e TXs redigidos; painel/saldo SSE vazios
Conta pkey no keystore Payload completo quando é parte (payer/payee, owner create/close, destination); saldo próprio no SSE
Audit pkey = validator Tudo em claro; painel total + lista de saldos no SSE

Redação (visão pública)

  • IDs de conta → public key opaca quando aplicável
  • Itens, assinaturas e campos sensíveis → tokens derivados (hash)
  • Create/close públicos: timestamp + public_key + assinatura opaca

Explorer

O login do explorer reconecta o SSE com /v1/chain?pkey=…. Logout volta à conexão anônima.

Listagens GET /v1/accounts e balance por ID permanecem públicas (saldos em claro). A redação aplica-se a blocos, TXs e eventos SSE de painel/saldo contextual.

Exemplos

# Bloco com visão de conta
curl -s 'http://localhost/v1/blocks/latest?pkey=<pkey>' | jq .

# Mesmo com header
curl -s http://localhost/v1/blocks/latest \
  -H 'X-Private-Key: <pkey>' | jq .
